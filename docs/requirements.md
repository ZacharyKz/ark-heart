> 纯业务需求，不涉及技术实现。技术栈由 Dev 在 project.md 中定义。
> 版本：V1 · 最后更新：2026-06-12

---

## 一、用户价值

- **谁会用？**
  - 来访者：在爱情/婚姻、亲子互动、职场人际中感到焦虑，寻求专业咨询帮助的人
  - 管理员：工作室运营者，负责接单、分配咨询师、发报告、统计数据

- **解决什么问题？**
  - 来访者能自助提交咨询预约，不用加微信前就反复沟通
  - 管理员有一个统一的后台管理系统，告别 Excel 和微信聊天管理预约

- **成功怎么衡量？**
  - 来访者能独立完成预约流程（从打开小程序到提交，不需中途放弃）
  - 管理员能在一个后台完成"查看预约 → 分配咨询师 → 确认 → 写报告 → 统计"全流程

## 二、用户故事

```
作为 来访者
我想要 浏览咨询方向并填写预约表单
以便 表达我的困扰并等待管理员帮我匹配合适的咨询师

```
作为 来访者
我想要 取消已有的预约
以便 在情况变化时撤回申请

```
作为 来访者

以便 知道预约进度和咨询师给我的反馈

作为 管理员

```

```
作为 管理员
我想要 确认预约并在后台写评估报告发给用户

```

## 三、核心流程

### 来访者预约流程

```
1. 用户打开微信小程序 → 看到咨询方向介绍（爱情/婚姻、亲子互动、职场人际）
2. 点击"立即预约" → 微信一键授权登录
3. 填写预约表单（姓名、手机号、微信号、性别、年龄、咨询方向、问题简述、咨询方式偏好）
4. 提交预约 → 提示"预约已提交，管理员将通过微信联系您确认时间"
5. 管理员联系并确认后 → 来访者收到订阅消息通知
6. 来访者在"我的"页面查看预约状态和报告
```

### 管理员工作流程

```
1. 管理员登录后台管理系统
2. 查看预约列表 → 筛选待处理预约
3. 加来访者微信沟通 → 联系咨询师确定时间
4. 在后台确认预约 → 来访者收到通知
5. 咨询结束后 → 管理员在后台写评估报告 → 发送给用户
6. 定期查看数据统计看板
```

| 字段 | 类型 | 必要性 | 说明 |
|------|------|--------|------|
| 姓名 | 文本 | 必填 | 用户称呼 |
| 手机号 | 文本 | 必填 | 11 位手机号 |
| 微信号 | 文本 | 必填 | 方便管理员添加 |
| 性别 | 单选 | 必填 | 男/女/不便透露 |

| 咨询方式偏好 | 单选 | 可选 | 线上/线下/均可 |

## 五、边界条件

- **空状态**：无预约记录时，"我的"页面展示引导文案"还没有预约记录"
- **加载状态**：表单提交时按钮显示 loading，后端处理中不可重复点击
- **错误状态**：网络异常时提示"网络不给力，请重试"；表单校验不通过时字段标红提示
- **极端数据**：问题简述限制 500 字，超长截断；手机号校验 11 位数字格式

## 六、范围定义

- **V1 最小可行**：
  - 预约表单 + 微信登录 + 管理员后台确认 + "我的"页面 + 取消预约
  - 报告系统 + 数据统计

- **明确不做**：
  - 在线支付
  - 来访者自助选咨询师/时段（由管理员分配）
  - 咨询师端登录（咨询师不登录系统）
  - 管理员拒绝预约功能（微信沟通后让用户自己取消）
  - 视频/语音咨询功能

- **后续迭代**：
  - 咨询师端小程序
  - 在线支付
  - 自助选时段
  - 咨询师评价体系

## 七、负面场景（必填）

### 权限
- 未登录 → 无法访问"我的"页面，跳转登录
- 非管理员访问后台 → 拒绝访问，返回登录页
- 用户只能看自己的预约和报告 → 不能看别人的

### 输入边界
- 必填字段为空 → 表单校验不通过，按钮置灰/提示
- 手机号格式不对 → 提示"请输入正确的手机号"
- 问题简述超过 500 字 → 截断提示或限制输入
- 特殊字符（emoji、脚本标签）→ 过滤或转义

### 操作限制
- 重复提交 → 按钮防抖，3 秒内不可重复点击
- 同一用户短时间内提交多个预约 → 弹窗确认"您已有待处理的预约，是否继续提交？"
- 已取消的预约不可再操作 → 状态置灰
- 管理员操作已被用户取消的预约 → 提示"该预约已被用户取消"

### 依赖异常
- 微信授权失败 → 提示"授权失败，请重试"，允许手动输入手机号
- 订阅消息发送失败 → 不影响主流程，记录日志
- 后端服务不可用 → 前端提示"服务繁忙，请稍后再试"
- 数据库异常 → 记录日志，返回友好错误提示
